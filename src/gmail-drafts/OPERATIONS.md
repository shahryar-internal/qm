# Gmail draft broker database rollout

Keep the broker disabled and drain all admission, broker, and reconciliation workers before changing the schema. PostgreSQL 16 is the only supported major version; the migration and role-binding script fail closed if its edge-level `ADMIN`, `INHERIT`, and `SET` membership semantics are unavailable. Precreate three distinct login roles: one `LOGIN NOINHERIT` deployment owner and two `LOGIN INHERIT` runtime principals. All three must be otherwise unprivileged, own no objects, hold no direct ACLs or default ACLs, be granted to no role, and have no unrelated membership. Apply `migration.sql` with a superuser and no Gmail draft login settings on the first install. The migration creates the three protected `NOLOGIN NOINHERIT` roles without members, takes access-exclusive locks on every existing broker table before auditing it, and supports either an empty database or the exact `gmail-draft-broker-active-lineage-v1` predecessor. It rejects every other pre-existing column, default, nullability, persistence, constraint, index, owner, grant, role posture, membership graph, trigger, policy, rule, inheritance, type, sequence, column ACL, owner-wide default ACL, or unrelated cluster-catalog privilege shape. Existing function signatures must be exact; their bodies and security properties are rebuilt while the tables remain exclusively locked and audited again before commit.

The v1 upgrade takes an access-exclusive lock on `approved_intents`, adds the reconciliation nonce, replaces the two completion functions with nonce-fenced signatures, and records `gmail-draft-broker-reconciliation-fence-v2` in the same transaction. Do not start a v2 process against a v1 schema or restart a v1 process after the migration commits.

Bind the three intended logins after the migration with:

```sh
PGOPTIONS="-c gmail_draft_broker.owner_login_role=YOUR_DEPLOYMENT_LOGIN -c gmail_draft_broker.admission_login_role=YOUR_ADMISSION_LOGIN -c gmail_draft_broker.broker_login_role=YOUR_BROKER_LOGIN" \
  psql "$PRIVILEGED_DATABASE_URL" -v ON_ERROR_STOP=1 -f src/gmail-drafts/runtime-role-bindings.sql
```

The binding script accepts no passwords or tokens. It requires a superuser, rejects privileged or multiply connected login roles, revokes every prior member of all three protected roles, and establishes exactly one edge per role. The owner edge is `ADMIN FALSE, INHERIT FALSE, SET TRUE`; the admission and broker edges are `ADMIN FALSE, INHERIT TRUE, SET FALSE`. It then audits database, schema, relation, sequence, column, function, type, trigger, default-ACL, ownership, and role-graph catalogs before commit. Use the admission login only for `createPostgresGmailDraftApprovalAdmissionStore` and the broker login only for `createPostgresGmailDraftExecutionStore`. Re-run `migration.sql` with the same three `PGOPTIONS` settings as the final post-bind audit; it accepts only the three intended direct isolated login bindings and exact catalog authority.

Enable the feature only after the private credential adapter reports the exact `qm-gmail-draft-private-transport-allowlist` contract, all private ports report ready, the real-PostgreSQL race test passes, and private Gmail/Slack acceptance tests pass.

Both PostgreSQL stores start unready. Run `gmailDraftBrokerStartupDoctor` before admitting or executing work. Its admission probe must authenticate as the one login bound only to `qm_gmail_draft_admission`; its execution probe must authenticate as the distinct login bound only to `qm_gmail_draft_broker`. The probes reject role switching, superusers and other privileged logins, PostgreSQL versions other than 16, missing or foreign schemas, unexpected relations or routine signatures, table or column access, and any effective routine grant outside the exact role allowlist. Do not reuse the application `DATABASE_URL`, a migration URL, or a privileged operator URL for either runtime connection.

The public repository intentionally has no implementations for the seven private ports and therefore no production route, admission worker, execution worker, reconciliation worker, or owner-DM publication wiring. Keep the capability default-off until a private deployment layer supplies the credential-opaque signer, thread verifier, admission connection, credential adapter, intent cipher, review authority route, and owner-DM publisher, then composes both PostgreSQL stores and the existing broker. That private composition must expose no token and no Gmail send capability. Run private Gmail and Slack acceptance in Chrome, never Firefox, and verify create, update, reconciliation, and owner-DM review while confirming that no message is sent.
