# Canonical canary integration boundary

This provider-free boundary validates public Chief-of-Staff, Revenue, and Marketing outputs and adapts their complete cited record, content digest, status, trust, and claim linkage into the six shared contracts. It renders only generic actionless surface identities. The closed `PublicationEnvelope` contains no provider payload, arbitrary narrative, action, or personal data.

The production-public CEO-surface facade validates the shared event and envelope before translating them into the fixed version-five durable store contract. It currently exposes canonical enqueue and read only. Its provider-free fixture exercises that same facade and verifies exact artifact reference, revision, artifact digest, evaluation digest, event identity, and envelope identity across storage, Slack, QM, and Notion. Claiming, reservation, and Slack delivery remain blocked on authenticated evaluation, outbox ingress, identity resolution, target resolution, provider receipt authority, and a reviewed Slack adapter.

Calendar binding, provider occurrence projection, lifecycle supersession, transcript verification, and global Gmail quota records are prospective contracts. Calendar and transcript broker receipts are unauthenticated and explicitly unverified. Lifecycle records require exact nonempty related records, occurrence revisions, and claim fences but cannot commit or report a reservation. The global Gmail helper applies fixed policy, counts outreach and transactional effects together, validates real UTC dates, and derives day-bound dedupe identities, but has no atomic reservation store and therefore always reports `approved: false` and `reserved: false`.

The separate Gmail adapter creates only a dormant `google.gmail.drafts.create` proposal bound to the canonical CEO mailbox and Google account owner, exact recipients, subject, body, evidence, and payload digest. Provider execution is unconditionally unavailable. No shared or integration barrel exposes a send or draft-send capability.

Recursive composition checks start at every canary public `index.mjs` root and follow every static relative import. Cross-package imports must enter through an `index.mjs` barrel. `actions`, `contracts`, and `workflows` are one documented legacy runtime-foundation package for this rule; private imports among those three directories remain internal foundation usage rather than public lane composition.
