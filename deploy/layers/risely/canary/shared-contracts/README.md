# CEO canary public contracts

This package is the only cross-lane public vocabulary. Chief of Staff, revenue, marketing, presentation, and durable-surface internals remain independently versioned and are not structurally identical to these contracts. Their public outputs cross one descriptor-safe adapter in `../integration/index.mjs`.

`PrincipalBinding`, `EvidenceBundle`, `WorkflowArtifact`, `EvalRelease`, `OutboxEvent`, and `PublicationEnvelope` have exact version-one schemas and named digest revisions. The principal binding fixes the Risely organization and CEO deployment, principal, mailbox, QM principal, credential owner, CEO-private audience, and logical Slack identities. Historical values are not alternate identities; the closed legacy table exists only to make migration explicit.

An outbox event id is derived from deployment, principal, artifact reference, revision, surface, and audience. The caller never supplies it. The public CEO-surface facade accepts only a validated `OutboxEvent` and its derived `PublicationEnvelope`, translates them into the existing version-five storage contract, and preserves the canonical artifact reference, revision, artifact digest, evaluation digest, and envelope digest. Legacy surface contracts and the version-five translation are private implementation details. Schema version six adds a permanently immutable event-identity tombstone for expired evaluation and identity-resolution records so a retained derived tuple cannot be reused with changed evaluation or envelope content.

`PublicationEnvelope` has no public builder. Its closed actionless payload is derived from the exact event, artifact, evaluation release, audience, and surface. It persists only the evidence-bundle digest, evidence count, opaque evidence references, and closed status, trust, and availability enums. Complete record, content, related-content, and claim lineage remains in the validated `WorkflowArtifact`, not the publication payload. The envelope cannot carry arbitrary fields, actions, narrative, personal identifiers, or a caller-chosen digest.

Gmail proposals are not part of this six-type shared vocabulary. The integration lane has a separate inert `google.gmail.drafts.create` adapter that binds the exact mailbox, Google provider owner, recipients, subject, body, evidence digest, and complete payload digest. It has no executor and declares execution unavailable.

All contracts and adapters are provider-free. Structural broker receipts are prospective and explicitly unresolved; hashes do not authenticate a broker. Historical aliases are available only from the private migration-ingress module, use own-property lookup, and are never emitted. Live activation still requires authenticated evaluation and outbox ingress, a connector-binding broker, source-verification broker, identity resolver, Slack adapter, Docker identity migration, independent review, and explicit activation.
