# CEO shadow acceptance harness

This provider-free harness composes only deployment-layer public barrels. It does not read credentials, environment variables, a database, the network, Slack, Google, Notion, AWS, or Command Center. Every surface is an actionless projection and every Calendar binding receipt remains explicitly unresolved.

## Proven in this harness

- One sanitized Calendar meeting produces the Chief-of-Staff T-24-hour, T-90-minute, and T-15-minute jobs with stable schedule revisions and dependency order.
- A moved occurrence cancels the old revision through fenced compare-and-swap drafts and schedules a new revision. A cancelled occurrence produces provider-cancelled drafts and no replacement jobs.
- Calendar unavailability produces no inferred deletion and no work. Unavailable dossier sources remain visible as missing context while available evidence stays cited.
- A normalized meeting dossier crosses an acceptance-local pure adapter into the public shared workflow artifact contract, the closed evaluation-release authority, three canonical outbox events and validated publication envelopes, and fixed actionless Slack, QM, and private-CEO Notion projections.
- The provider-free version-six behavioral fake accepts exact replay, rejects changed content under the same event identity, and retains immutable expiry tombstones.
- A pending transcript waits. A unique final transcript reaches the public `verification_required` correlation and analysis-input boundary through the non-exact time-and-participant path with no provider action enabled.
- Descriptor-safe public contract validation rejects accessors and detectable proxies without invoking their code. Generic surface content omits workflow narrative, attendee email addresses, meeting titles, and secret-shaped strings.

The evaluation-release authority reruns deterministic checks over the actual normalized dossier, reconstructs every artifact, evidence, payload, profile, policy, and result binding, and verifies two separately keyed synthetic judge records before minting a shadow release. Tests generate ephemeral signing keys in process; no fixture private key is stored in the repository. The fixture simulates distinct origins but does not prove two real independent judge executions. Production code contains no judge-result mint, trust-root instance, model client, provider adapter, network path, or ambient configuration access. A durable append-only result, release, and replay-tombstone store remains required before activation.

## Prospective behavior and activation blockers

The production canonical CEO-surface facade exposes its class publicly but its provider-free binder is private. The acceptance-owned facade therefore validates the same shared `OutboxEvent` and `PublicationEnvelope` contracts and exercises a behavioral version-six fake. It does not prove PostgreSQL durability, transaction locks, migrations, runtime identity resolution, or production facade wiring.

The shared canonical event has an evaluation expiry but no identity-resolution receipt. This fake therefore models the evaluation event-identity tombstone only; it cannot prove the separate identity-resolution expiry tombstone in the PostgreSQL version-six schema. Its in-process map can demonstrate retention beyond 180 days within one test object, not durable retention across a restart.

There is no narrow public pure Calendar-to-scheduler adapter. The acceptance-local projection and public Chief-of-Staff scheduler use different occurrence references and attendee response spellings. The bridge binds both projections to the same provider event and evidence digest, but an upstream public canonical adapter is still required before activation. The acceptance lane intentionally does not import the broad integration barrel because its transitive graph is outside this provider-free proof.

Chief of Staff has no public adapter from its verified post-meeting analysis input into a shared `WorkflowArtifact`. The trusted source-verification broker also has no public receipt mint. Final transcript processing therefore stops honestly at `verification_required`; it cannot create a Gmail draft, proposal, canonical post-meeting artifact, outbox event, or surface publication.

The transcript provider-account anchor and evidence digest are carried into the verification request, but the acceptance layer cannot authenticate them. That requires the missing broker receipt. No exact Calendar event or occurrence identity is copied into the transcript; caller attempts to add either are rejected. The public dossier is structurally validated rather than opaque-branded; this harness creates it through the public normalizer and brands its dossier, schedule, and compiled meeting-prep boundaries locally.

Chief-of-Staff source inventory distinguishes `available`, `unavailable`, and `not_connected`. It does not expose Revenue's successful-empty `none` state, so this harness does not claim that distinction. No Gmail draft or quota reservation is composed here: the public post-meeting boundary is dormant before draft creation. Throwing Gmail, Google, Notion, and Slack ports are injected into the behavioral store and remain uncalled. A fresh-process sentinel also verifies that importing this lane performs no attributable environment, network, or database access.

No result from this directory authorizes a provider call or production deployment.
