# CEO private surface security boundary

This package is a shadow-only publication compiler and explicit-pool Postgres adapter outside QM plugin discovery. Its public production surface is the canonical durable facade, which accepts only a validated shared `OutboxEvent` and its exact derived `PublicationEnvelope`; legacy compiler, receipt, and version-five translation types remain private modules. The facade currently exposes canonical enqueue and read only. Canonical claiming, reservation, authenticated receipt acceptance, and provider delivery remain activation blockers. It has no server, deployment definition, credential reader, environment reader, network client, live adapter, or provider invocation path. Production startup always throws.

The compiler accepts one closed durable-outbox envelope. The envelope contains a typed presentation artifact, the exact artifact-revision digest, a release receipt from the shadow evaluation gate, the deployment-binding digest, and its own canonical payload digest. The evaluation receipt must bind the same artifact id, revision, and digest; record zero side effects; contain the complete deterministic gate set and two independently signed judge results with distinct identities, origins, and classes; be unexpired; and declare both pass and release. Candidate and judge records keep deployment-profile, evaluation-profile, and evaluation-policy digests distinct, while the release binds the exact policy reference and digest. The version-8 adapter also requires the exact same-profile release to exist in the append-only evaluation ledger before enqueue, then rechecks its expiry and explicit provider ineligibility during claim and reservation. Receipt hashes alone are not release authority. Activation requires the deployment binding to be anchored outside request data and authenticated composition with the exact evaluation authority, result store, outbox writer, and identity resolver.

The deployment binding fixes the public `PrincipalBinding` identity: `organization:risely`, `deployment:risely:ceo-canary:v1`, `principal:ceo`, `shahryar@risely.ai`, `qm:principal:ceo-canary`, `credential-owner:ceo`, `slack-audience:ceo-private`, `slack-team:risely`, and `slack-user:ceo`. It also fixes the QM authenticated root, OIDC authentication mode, shadow delivery mode, evaluation authority and policy digest, and identity-resolver authority. The artifact and outbox cannot carry a Slack destination. A future reviewed identity resolver must return a canonical Slack team, CEO user, and direct-message conversation in a digest-bound receipt that exactly matches the deployment identity.

Artifact links are discarded. Slack output is rebuilt with an empty interaction registry, so no buttons, actions, interaction references, or provider commands survive. Slack-visible plain text that could be auto-linked as a scheme, domain, email address, or IP address is rejected. The compiler adds exactly one link: the deployment-owned authenticated QM root. The URL has no bearer value, query, fragment, or per-message authorization material; authentication remains the responsibility of the QM OIDC session.

Every outbox event id is derived and revalidated from deployment, principal, artifact reference, digest revision, Slack surface, and audience. A caller cannot choose a second event id for the same tuple. Every compiled shadow publication has a delivery key over only the deployment binding and that derived durable event identity. The sole initial version-8 migration gives the event a primary key, one reservation per event, a permanent tombstone for terminal delivery, and a separate permanent event-identity tombstone for evaluation-release and identity-resolution expiry; enqueue checks event, payload, and derived identity digests against it before any insert. Atomic reservation stores the complete short-lived identity receipt and actionless publication and treats the payload, immutable artifact, exact identity receipt, Slack target, credential owner, and rendered message as conflict fields, so any changed value stops the same event instead of creating a second delivery. PostgreSQL reservation time is the permanent authority time for that publication: the evaluation and identity receipts must be valid then, and all later reconciliation, receipt, tombstone, and retained-history checks reconstruct the compiler output against that recorded time instead of the wall clock. The attempt moves from `reserved` to `attempting` in PostgreSQL before a future publisher may invoke Slack. A process loss after that transition is never claimable for another delivery attempt. It must enter the revisioned outcome-unknown reconciliation path after the fixed uncertainty interval.

Receipts are append-only, bind every publication digest and the stable internal attempt reference, and are updated atomically with reservation and outbox state. Only a structurally verified receipt may contain a provider receipt reference. For outcome-unknown, `completedAt` means the time ambiguity was durably classified, not proof of provider completion. A terminal commit also creates an immutable permanent delivery tombstone containing the exact evaluated outbox envelope, identity receipt, compiler-authentic publication, complete receipt lineage, and terminal audit request binding. Expiry atomically creates an immutable event tombstone containing the event, deployment, payload, artifact, evaluation, and any resolved identity, target, and message conflict digests. Retention may remove corresponding live rows after 180 days only when every conflict field matches the appropriate tombstone; it never removes either tombstone. Pending, claimed, attempting, and outcome-unknown records remain live. Process memory is not an outbox, idempotency store, receipt store, or reconciliation source of truth.

Receipt field lists, hashing, and structural storage are prospective serialization contracts, not receipt authority. The internal generic receipt validator still rejects every validation attempt, including caller-forged copies that flip shadow flags. The durable store can exercise structurally bound receipts in disposable tests, but production receipt acceptance still requires an authenticated Slack-adapter receipt, the existing durable event reservation, and exact publication conflict bindings in a separate reviewed live composition.

Durability-interface validation rejects accessor-backed objects and detectable proxies, captures each method reference once, and returns a new frozen facade. Future composition must retain only that returned facade; mutating the source adapter after validation cannot change its metadata or replace its captured methods. These structural checks do not prove that a method's closure truly uses Postgres, so adapter implementation review and database integration evidence remain activation requirements.

The adapter cannot expose method facades or execute any business query until initialization completes the fixed canary verifier for database, schema, role, migration checksum, complete catalog definitions, owners, memberships, search path, triggers, namespace features, and ACLs. Initialization is not trusted as a lasting statement about a caller-owned pool: every acquired client begins a transaction, takes the shared maintenance lock, and performs the same-client immutable sentinel check for database, runtime role, namespace, sole version-8 checksum, catalog-authority digest, exact deployment-profile pair, and evaluation privileges before any surface relation is queried. Changing pool options, its future connection target, database, role, profile, or privilege therefore fails before business SQL. Every mutation then takes a profile-and-entity advisory lock, while migration and retention take the maintenance lock exclusively. Full startup and periodic health attestation detect privileged external catalog drift outside the DDL-free runtime role. Receipt reads use a repeatable-read snapshot and revalidate the complete reservation, outbox, receipt, revision, hash, state, and tombstone lineage.

Activation is blocked until the sole version-8 migration runs in the exact empty bootstrapped schema on an approved isolated host whose database is named `qm`, the full catalog and ACL readiness check passes, the sole fixed `CANARY_DEPLOYMENT_PROFILE_REF` is rendered as `deployment-profile:risely:ceo:v1` and resolves through the immutable production registry, authenticated evaluation and outbox ingress exists, the exact production evaluation dependencies are present in the runtime image with test roots, keys, profiles, and stores excluded, the production evaluation authority accepts only the authentic frozen append-only PostgreSQL result-store port issued by an initialized separately credentialed evaluation writer, the runtime role is denied both raw evaluation inserts and routine execution, a reviewed authenticated identity resolver and Slack-delivery adapter exist, an independent security review approves the composition, and a separate explicit production startup implementation is reviewed. The evaluation-writer role remains `NOLOGIN` and uncredentialed in production until its workload boundary receives separate review. No legacy Docker identity alias or migration-ingress mapping is accepted. Provider execution remains hard-disabled. This package must never receive the QM core signer, a Slack socket token, or a caller-selected destination.
